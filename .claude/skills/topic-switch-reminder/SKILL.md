# 話題切り替えの注意

## 目的

話題が変わっても同じ会話を続けると、それまでのやりとりを毎回読み直すぶん利用量が増え、前の話題に引っぱられて回答の精度も落ちる。切り替わったタイミングで、ユーザーに新しい会話を始めるよう一言で促す。

## 切り替わりとみなす場合

次のどれかに当てはまるとき。

- 作業の種類が変わった（判定メモ → 画像制作、口コミ作成 → 環境設定の相談 など）
- 対象のアカウント・プロジェクト・リポジトリが変わった
- 直前までの会話の内容を、新しい依頼にほぼ使わない

次の場合は切り替わりとみなさない（注意を出さない）。

- 同じ作業の続き（次の投稿リンクの判定、直前の回答の修正・深掘り・保存）
- 直前の結論を使って次の作業に進む場合（判定メモで「試す」とした案の実行 など）
- 会話がまだ短い（目安：ユーザーの発言が3回以下）

迷ったら出さない。

## 出し方

1. 依頼にはいつもどおり答える。注意を理由に回答を断ったり、後回しにしたりしない。
2. 回答の**最後**に、次の形式で短く添える。

```
---
💡 話題が「{前の話題}」から「{新しい話題}」に変わりました。新しい会話で始めると、利用量を抑えられて回答の精度も上がります。
続ける場合は、新しい会話の最初に次の引き継ぎメモを貼ってください。

> 引き継ぎメモ：{新しい依頼に必要な前提だけを3行以内で}
```

3. 同じ切り替わりについて注意を出すのは1回だけ。ユーザーが「このまま続けて」などと答えたら、その会話では以後出さない。

## 引き継ぎメモの書き方

- 新しい依頼に必要な事実・決定事項だけを書く（例：対象アカウント、決まった方針、使うファイル名）
- 前の話題の経緯や結論は、新しい依頼に関係するものだけにする
- 3行以内
